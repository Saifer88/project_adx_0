# ADX compiler Milestone 1 — single-component build/check pipeline

The branch adds a TypeScript/Node ESM compiler under `compiler/` that turns one `.adx` component directory into complete static HTML, scoped plain CSS, and a hydration-only ES-module glue script. It implements the full front-end (tokenizer, recursive-descent structure parser, manifest/token loaders, behavior export scanner, build-time expression evaluator), the three codegen emitters, an end-to-end `compileComponent`/`checkComponent` pipeline, and an `adx build` / `adx check` CLI. Design tokens live at the worktree root (`tokens/design-tokens.json`) and resolve at build time. Docs were flipped from "planned" to real only for the implemented slice. Watch for: nothing blocking — all six M1 non-negotiables hold and build/tests/lint are green (confirmed).

**Verdict**: APPROVED

## High-level view

The compiler resolves every `{{interpolation}}` and `:prop` at build time, so the emitted `index.html` is complete crawlable content with zero `{{` left and the glue only hydrates — the SEO contract holds (confirmed by running the CLI and inspecting output). The glue imports behavior exports from `./behavior.js`, calls `setup(props)` once, and wires events by selecting existing nodes via `data-adx-c`/`data-adx-b`; there is no vDOM, no shared runtime, and no `createElement`/`innerHTML` DOM construction (confirmed by source scan — the only match is a comment asserting the absence).

Diagnostics use the exact `[ADX] <file>:<line> - <message>` shape, with the line-less manifest variant, and the unknown-token error reproduces verbatim (`[ADX] style.adx.css:5 - Unknown token "tokens.space-5" (available: 0,1,2,3,4,6,8,12,16)`). The CLI exposes only `build` and `check`; any other subcommand prints usage and exits 1 (confirmed `adx dev` → exit 1).

A notable improvement over the FEAT-002 findings: the CLI now also copies `behavior.adx.js` to `dist/<name>/behavior.js`, so the glue's `./behavior.js` import actually resolves in the browser — the previously-noted runtime gap is closed. `dist/` and `node_modules/` are gitignored and not committed.

The page-level SEO rules (single `<h1>`, no heading-level skips, sitemap/robots) are deliberately out of M1 scope: this compiles a component fragment and wraps it in a document shell only for verification. The emitted `<h2>`-without-`<h1>` is an acknowledged fragment limitation, not a regression.

### SEO contract on real emitted HTML

Running `node dist/cli.js build fixtures/user-card --out dist` produces an `index.html` whose `<main>` carries the fully-resolved component markup: the `role` default `"User"` appears as text, the `:if="bio"` paragraph is omitted (empty default is falsy), and the named slot becomes a `data-adx-slot="actions"` placeholder. `grep -c "{{"` returns 0. The document shell emits `lang`, `<title>`, description, canonical, Open Graph and Twitter tags from `manifest.seo` (falling back to the component name), optional JSON-LD when `seo.schema` is set, and loads the glue as `<script type="module" src="glue.js">` placed after `</head>` so it never blocks first paint. This satisfies the "content in the HTML, not injected by JS" requirement at the component level.

### Hydration-only glue

`emitGlue` produces an ES module that imports `setup` plus the unique sorted event-handler names from `./behavior.js`, builds props from manifest defaults merged with `globalThis.__ADX_PROPS__` overrides, installs a bubbling-`CustomEvent` `emit` before calling `setup(props)` once, then selects the root by `data-adx-c` and hooked nodes by `data-adx-b` to attach listeners `(event) => handler(state, event)`. A source-wide scan for `createElement`/`innerHTML`/vDOM finds only a comment in `glue.ts` documenting their deliberate absence. No shared-runtime import exists — the only import is the component's own behavior module.

### Error format and token resolution

`errors.ts` formats `[ADX] <file>:<line> - <message>` and a line-less `[ADX] <file> - <message>` for manifest errors. `transformCss` threads absolute source offsets through its brace-matching walk (including inside `@media`) so the unknown-token line is accurate, and throws the exact contract string — reproduced here as `[ADX] style.adx.css:5 - Unknown token "tokens.space-5" (available: 0,1,2,3,4,6,8,12,16)` on a broken fixture copy (`check` exit 1). Tokens resolve from `tokens/design-tokens.json` at the worktree root; CSS output shows `tokens.space-4` → `16px`, `tokens.radius-lg` → `12px`, `tokens.shadow-md` → the resolved shadow, and selectors scoped as `.card[data-adx-c="cba1d828"]` with `:hover` preserved after the attribute.

### CLI surface and output layout

`cli.ts` parses only `build`/`check` with `--out` and `--tokens`; an unknown or missing command prints usage and exits 1 (`adx dev` confirmed exit 1). `build` writes `index.html`, `style.css`, `glue.js`, and `behavior.js` under `dist/<dir-basename>/`; `check` validates and emits in memory, prints `OK`, writes nothing. The scope id is a deterministic hash of component name + directory basename (`UserCard@user-card` → `cba1d828`).

### Verification evidence

`npm run build` (tsc) is clean, `npm test` passes 77 tests across 11 files, `npm run lint` (eslint) exits 0. The working tree is clean; `dist/` and `node_modules/` are gitignored and absent from `git ls-files`.
